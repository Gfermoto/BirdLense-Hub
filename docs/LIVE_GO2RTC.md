# Live-потоки и go2rtc (502 / чёрный экран)

## Что проверено

- **500 Internal Server Error** при `/go2rtc/stream.html` — исправлено: в nginx убраны переменные из `proxy_pass` (используется `rewrite ... break` и `proxy_pass http://UPSTREAM;`).
- **502 Bad Gateway** — контейнер не может достучаться до go2rtc. Это не ошибка кода, а настройка окружения.

## Что сделать, если в Live 502 или чёрный экран

1. **go2rtc должен быть запущен** на той же машине или в сети, доступной с хоста, где крутится BirdLense.

2. **URL не подменяется.** Указывайте тот адрес, с которого контейнер реально достучится до go2rtc:
   - **network_mode: host** — используйте **http://localhost:1984** (контейнер = сеть хоста).
   - **bridge** — **http://172.17.0.1:1984** или **http://IP_хоста:1984** (localhost из контейнера = сам контейнер).

3. **go2rtc на хосте должен слушать 0.0.0.0:1984**, а не только 127.0.0.1, чтобы контейнер мог подключиться по 172.17.0.1.

4. **Проверка с хоста** (где запущен Docker):
   ```bash
   curl -s -o /dev/null -w "%{http_code}" http://172.17.0.1:1984/api/streams
   ```
   Ожидается 200. Если connection refused — go2rtc не запущен или не слушает на этом интерфейсе.

5. **Временный обходной путь в UI**: на странице Live нажмите **«MJPEG»** — поток пойдёт через процессор (одна камера с картинкой, остальные могут быть чёрными, т.к. процессор декодирует только активную камеру).

## Цепочка как во Frigate

- **Настройки → Видео → Go2RTC URL**: один раз указать адрес go2rtc (например `http://172.17.0.1:1984`).
- **Камеры**: `stream_name` должен совпадать с именем потока в go2rtc.
- Live по умолчанию отдаёт RTC/MSE через go2rtc; при недоступности go2rtc — использовать кнопку MJPEG в интерфейсе.
