# Guardrails для тюнинга на проде

Короткий регламент, чтобы любые изменения CV/trigger-настроек на проде были проверяемыми и обратимыми.

## 1) Перед изменением

- Зафиксировать целевой эффект в 1-2 строках:
  - что уменьшаем (например, пустые IR-записи ночью),
  - что не ломаем (реальные птицы/грызуны должны продолжать проходить).
- Подготовить откат:
  - backup `app_config/user_config.yaml`,
  - команда отката.
- Явно обозначить риск:
  - риск пропуска слабых событий,
  - риск роста ложных срабатываний.

## 2) Изменять только одну гипотезу за шаг

- Нельзя одновременно менять всё подряд.
- Приоритет тюнинга:
  1. `triggers.opencv.*` (частота/чувствительность/площадь),
  2. `processor.adaptive_profiles.night.*` для IR/низкого контраста,
  3. только потом confidence/track thresholds.

## 3) После изменения — только факты

Обязательный минимум доказательств:

- `StartedAt` контейнера после рестарта.
- Effective runtime config из контейнера:
  - `active triggers`,
  - `opencv`,
  - `frigate`,
  - ключи `motion.*`,
  - `night.*`.
- Логи по триггерам за последние 15-20 минут.
- `health/readiness` статусы.

## 4) Откат

- Если эффект хуже или непонятен — откат сразу.
- Нельзя оставлять сомнительный hotfix «до потом».

## 5) Инструмент проверки

Используйте скрипт:

```bash
./scripts/prod/verify-trigger-state.sh
```

Он печатает:

- целевой сервер деплоя,
- время старта контейнера,
- effective trigger/runtime значения,
- релевантные строки логов по motion/Frigate trigger.
