# Инцидент 2026-03-14: Сброс пароля настроек

## Что произошло

При добавлении маскирования секретов в API (`GET /api/ui/settings` возвращает `***` вместо реальных значений) была допущена ошибка в `filter_sensitive_placeholders`: **пустая строка не фильтровалась**.

При сохранении настроек, если поле пароля оказывалось пустым (например, из-за особенностей отображения masked-значения в форме), реальный пароль перезаписывался пустой строкой. Вход в настройки становился невозможным.

## Исправления

1. **app_config.py** — `filter_sensitive_placeholders` теперь игнорирует и пустые строки для секретов (не только `***`).
2. **scripts/fix-settings-password.sh** — скрипт восстановления доступа на сервере.

## Восстановление

```bash
ssh root@192.168.1.11 'bash -s' < scripts/fix-settings-password.sh
```

**Важно:** Не передавайте пароль в чат или логи. Используйте `E2E_SETTINGS_PASSWORD` только в переменных окружения при локальном запуске тестов.

Или вручную:
```bash
ssh root@192.168.1.11
nano /root/BirdLense/app/app_config/user_config.yaml
# В general: settings_password: ""
docker restart birdlense
```
