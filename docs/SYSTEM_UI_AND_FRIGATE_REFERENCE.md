# System UI, ресурсы, логи и эталон Frigate NVR

## 1. MQTT — что может быть «не то»

В BirdLense **два отдельных MQTT-клиента**:

| Клиент | Где | Назначение | Статус в UI |
|--------|-----|------------|-------------|
| **Web (feed_service)** | Контейнер web | Кормушка (dispense), проверка `check_mqtt_connected()` | Индикатор MQTT на главной (status) |
| **Процессор (mqtt_aggregator)** | Контейнер processor | Frigate/BirdNET события, публикация в birdlense/detections | Раньше не отображался |

Если в логах процессора видны **циклические disconnect/reconnect** MQTT, это агрегатор процессора (Frigate/BirdNET). Индикатор в шапке мог показывать только статус **веб-**клиента (кормушка). Поэтому создаётся впечатление «с MQTT что‑то не то»: по UI непонятно, подключён ли процессор к брокеру.

**Что сделано:** в heartbeat процессора добавлены поля `mqtt_connected` и `encoding_used`. В System и/или в статусе можно показывать «Processor MQTT» и «Кодирование записи: CPU / VA-API» по данным от процессора.

**Рекомендации по диагностике MQTT:**
- Логи процессора: `docker logs birdlense 2>&1 | grep -i mqtt` — искать "connected", "disconnect", "reconnect".
- Проверить лимиты соединений на брокере (два клиента: birdlense_aggregator и веб для кормушки).
- Убедиться, что `mqtt.broker`, `mqtt.port`, топики Frigate/BirdNET и при необходимости `MQTT_USERNAME`/`MQTT_PASSWORD` совпадают с настройками брокера и Frigate.

## 2. Загрузка и использование GPU в интерфейсе

Раньше в System отображались только **CPU, память, диск**. Не было:
- текущего режима кодирования записи (CPU / Intel GPU);
- факта использования VA-API в последней записи.

**Что сделано:**
- В **метрики** (`/api/ui/system/metrics`) добавлены поля `encoding` (из конфига: `cpu` | `intel`) и при наличии heartbeat — `encoding_used` (фактически использовано: `cpu` | `vaapi`).
- На странице **System** добавлен блок **«Кодирование записи»**: настройка (CPU / Intel GPU) и фактическое использование по данным процессора (например: «Сейчас: Intel GPU (VA-API)» или «Сейчас: CPU»).
- Опционально в контейнере с GPU можно позже добавить чтение загрузки из sysfs/Prometheus (как во Frigate); для первого шага достаточно отображения режима и факта VA-API.

## 3. Эталон: Frigate NVR — информативность ресурсов и логов

По [документации](https://docs.frigate.video/configuration/metrics/) и обсуждениям:

| Аспект | Frigate | BirdLense (после доработок) |
|--------|---------|-----------------------------|
| **Метрики** | Prometheus `/api/metrics`: GPU %, CPU %, память, FPS камер, детектор | `/api/ui/system/metrics`: CPU, память, диск, encoding, encoding_used; при желании позже — Prometheus-эндпоинт |
| **System page** | Графики CPU/memory/GPU, обновление ~10 с, окно 10 мин | Карточки CPU, память, диск, кодирование; автообновление 5 с |
| **Логи** | Логи в память, стриминг в UI, дедупликация «Last message repeated N times» | Файл `processor.log`, последние N строк по запросу; автообновление раз в 10 с, кнопка «Обновить» |
| **Детектор/запись** | Разбивка по процессам (ffmpeg, detect, capture) | Режим кодирования (CPU/VA-API) из heartbeat |

**Реализовано по образцу Frigate:**
- Отдельная страница System с ресурсами (CPU, память, диск) и блоком кодирования (GPU/CPU).
- Метрики с автообновлением (интервал 5 с).
- Логи процессора с выбором количества строк и автообновлением (10 с), моноширинный блок с прокруткой.
