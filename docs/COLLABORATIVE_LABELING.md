# Совместная разметка (Collaborative Labeling)

Концепция: все пользователи BirdLense Hub участвуют в разметке детекций — подтверждают или исправляют вид птицы. Данные идут на благо сообщества: улучшение моделей, общие датасеты.

Аналог: [Frigate](https://docs.frigate.video) — пользователи подтверждают/исправляют детекции в UI, данные используются для улучшения моделей.

---

## 1. UI (как во Frigate)

### Где показывать

- **VideoDetails** — карточка каждой детекции (вид, confidence)
- Действия: **«Подтвердить»** ✓ | **«Исправить»** ✎

### Сценарии

| Действие | Значение |
|----------|----------|
| **Подтвердить** | Пользователь согласен: на картинке действительно этот вид |
| **Исправить** | Выбрать правильный вид из списка (Species) |
| **Ложное срабатывание** | «Не птица» / «Удалить» — не считать детекцией |

### Визуальная обратная связь

- Подтверждённые — зелёная галочка, «Проверено пользователем»
- Исправленные — показать: было X → стало Y
- Ложные — зачёркнутый вид, красная рамка (как во Frigate)

## 2. Модель данных

### Вариант A: Отдельная таблица (рекомендуется)

```
DetectionFeedback
  id
  video_species_id   -- ссылка на VideoSpecies
  action             -- 'confirm' | 'correct' | 'reject'
  corrected_species_id  -- при correct: новый вид
  created_at
  -- опционально: user_id (если есть авторизация)
```

**Плюсы:** сохраняем исходную модель-предсказание и человеческую правку. Для обучения используем `corrected_species_id` (или `species_id` при confirm).

### Вариант B: Поля в VideoSpecies

```
VideoSpecies
  ...
  user_confirmed     -- bool
  user_corrected_species_id  -- при исправлении
```

**Плюсы:** проще. **Минусы:** теряем историю (кто, когда, что менял).

## 3. Куда уходят данные

### 3.1 Локально (по умолчанию)

- Сохранение в локальную БД BirdLense Hub
- Используется для экспорта в YOLO и дообучения **своих** моделей
- Приватность: данные не покидают установку

### 3.2 Экспорт для обмена

- **Формат:** JSON/CSV с crop + label (вид)
- **Куда:** ручной выгрузка, загрузка на Zenodo, GitHub Dataset, OSF
- Пользователь сам решает, публиковать ли

### 3.3 Централизованный сбор (опционально)

- **API:** POST на внешний сервер с анонимизированными данными
- **Сервисы:** Roboflow, Label Studio, или свой backend
- **Приватность:** opt-in, без видео — только crop + вид, без геолокации

### 3.4 Сообщество BirdLense Hub

- **Hugging Face** — итеративные обновления, `load_dataset()`, удобно для ML
- **Zenodo** — снапшоты с DOI для цитирования в статьях
- Лицензия: CC BY или CC BY-SA для научного использования
- Подробнее: [DATASET_SOURCES.md](./DATASET_SOURCES.md)

## 4. Реализация (этапы)

### Этап 1: Локальная разметка
- [ ] Таблица `detection_feedback` (или поля в VideoSpecies)
- [ ] API: `POST /api/ui/videos/:id/species/:vs_id/confirm`, `.../correct`
- [ ] UI: кнопки «Подтвердить», «Исправить» в DetectedSpecies
- [ ] Экспорт: `export_birdlense_to_yolo.py` учитывает `user_confirmed` / `corrected_species_id`

### Этап 2: Визуальная обратная связь
- [ ] Отображение статуса (подтверждено / исправлено / отклонено)
- [ ] Фильтр в Timeline: «только проверенные»

### Этап 3: Куда отправлять (по выбору)
- [ ] Настройка: URL API для отправки разметки (opt-in)
- [ ] Или: кнопка «Экспортировать для сообщества» → выгрузка в стандартный формат

---

## 5. Приватность и этика

- **По умолчанию** — всё локально
- **Отправка куда-либо** — только с явного согласия пользователя
- **Анонимность** — не передавать IP, геолокацию, идентификаторы
- **Данные** — только crop изображения + вид, без привязки к месту/времени (если не нужно для исследования)
