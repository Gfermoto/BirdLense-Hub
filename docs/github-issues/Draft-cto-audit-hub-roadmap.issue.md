## Контекст

Стратегический разбор кодовой базы BirdLense Hub (монолит в контейнере, Flask API, процессор с YOLO/OpenVINO, SQLite, MQTT-интеграции): зафиксированы приоритеты безопасности, наблюдаемости, упрощения конфига и подготовки к росту нагрузки. Ниже — **бэклог с фазами** и резюме консилиума для ревью.

**Связанные документы:** `docs/SECURITY.md`, `docs/RUNTIME_COUPLING.md`, `docs/SETTINGS_TRIGGERS_PHASE2*.md`, `AGENTS.md`, `.github/workflows/ci-pr.yml`.

## Цели продукта (метрики)

1. **P95** время от триггера до появления клипа в UI.
2. **Доля** записей без приемлемых детекций при эталонном сценарии (день / кормушка).
3. **MTTR** типового инцидента без необходимости SSH (логи/дашборд < 15 мин).

## Фаза A — Foundation (0–6 недель)

| ID | Инициатива | Результат | Готово когда |
|----|------------|-----------|--------------|
| **A1** | Прод-барьеры: `BIRDLENSE_STRICT_API_AUTH`, MCP token при `mcp.enabled`, пароли настроек, явный **CORS** для VPS в доках деплоя | Меньше «LAN-режима» в открытой сети | Runbook pre-flight + скрипт `scripts/verify-prod-env.sh` (или pytest) в CI / перед `make deploy` |
| **A2** | Записи: для не-LAN — **не** отдавать `/data/recordings/` анонимно; signed URL / stream через API / **nginx IP allowlist** | Закрыть predictability URL | Проверки из `SECURITY.md` (curl) зелёные |
| **A3** | Наблюдаемость CV: счётчики за сессию записи (кадры, `yolo_ran`, light gate, воронка детекта) | Быстрый root-cause порогов/трекера | Одна строка structured log на finalize + пункт в `TROUBLESHOOTING` |
| **A4** | Инварианты конфига: например `detection.min_confidence_to_store` ≤ `processor.min_confidence_to_process`; согласование с floors | Меньше тихих конфликтов | Проверка при reload + юнит-тест |
| **A5** | Rate limiting (Flask-Limiter) на login / мутации | Закрыть gap из `SECURITY.md` | Конфиг + pytest smoke |

## Консилиум (ревью плана)

- **Security:** A1→A2→A5 — правильный порядок; A3 — не логировать чувствительные payload; A2 — **блокер** для публичного релиза.
- **SRE:** B2 требует метрик очереди/DLQ с первого дня; перед B1 — зафиксировать бюджет CPU/RAM процессора в compose.
- **ML/CV:** A3 + D2 — быстрый выигрыш; полный Pydantic-config **не** смешивать с горящей фазой A (только A4 узко).
- **Product:** дублировать A1 в UI **System → готовность к продакшену** (галочки), не только runbook.
- **Architecture:** WIP — **один** крупный инфра-epic на квартал; C1 optional для малых инсталляций.
