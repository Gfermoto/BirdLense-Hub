# GitHub Issues и доска — отчётность

[English](./PROJECT_REPORTING.md)

---

**Правило:** любая содержательная работа должна быть **отражена в GitHub** — в **Issues** и, если пункт есть на **доске**, на проекте **BirdLense Hub — Roadmap**. Это касается **всей** работы, не только строк из [консилиума в ROADMAP](./ROADMAP.ru.md).

## Зачем

- Прослеживаемость: что сделано, когда, в каком PR.
- Доска — единая картина статуса для вас и соавторов.

## Когда работа завершена (или частично сдана)

1. **Issue уже есть**  
   - Комментарий: кратко что сделано, ссылки на PR / коммит / тег релиза при необходимости.  
   - **Закрыть** issue, когда выполнены критерии готовности.  
   - Если карточка на Project: **Status** (и **Поток**, если используется) → **Done** — вручную в UI или  
     `bash scripts/github-project-mark-done.sh <номер> [ещё номера…]`  
     (нужен **classic PAT** с `repo` + `project` в `scripts/.env.project`; см. [GITHUB_SETUP_GH.ru.md](./GITHUB_SETUP_GH.ru.md)).

2. **Issue ещё нет**  
   - Завести **Issue** (метки `area:*`, `priority:*`), либо при размытой идее — **Discussion**, затем Issue.  
   - Добавить карточку на доску **Roadmap**, если это планируемая/текущая работа.

3. **Частичная поставка** (например фазы A+B готовы, C позже)  
   - Комментарий: что сделано и что осталось; issue **не закрывать**, пока объём не закрыт (или вынести хвост в отдельный issue со ссылкой).

4. **Работа вне таблицы консилиума** (CI, только доки, chore)  
   - Всё равно завести/использовать Issue (или один «зонтичный» chore на период), чтобы доска и история не расходились с реальностью.

## Автоматизация и доступ CLI

- Пометить Done на доске: **`scripts/github-project-mark-done.sh`**.  
- Если `gh project list` ругается на scope:  
  `gh auth refresh -s read:project`  
  (и scope на запись полей проекта, если правите доску из CLI).
