# Консилиум: только кропы в датасете

Документ для глубокого анализа и системного решения проблемы полноформатных изображений в датасете BirdLense.

---

## 1. Требования

| Требование | Описание |
|------------|----------|
| **Только кропы** | В датасете должны быть только кропнутые изображения (bbox птицы), не full-frame |
| **Источники** | Автосохранение (процессор) или ретроэкспорт |
| **Проверка** | YOLO детектирует «птицу» → пользователь вручную проверяет и исправляет вид |
| **Проблема** | В датасет попадали полноформатные изображения |

## 2. Аудит: откуда могли попасть full-frame

### 2.1 Потоки данных (схема)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ ИСТОЧНИК 1: Процессор (автосохранение)                                       │
│                                                                             │
│  YOLO → bbox → crop из кадра → best_frame (numpy array) → dataset_saver     │
│                                                                             │
│  best_frame ВСЕГДА = crop (frame_processor хранит crop из bbox)             │
│  → full-frame НЕВОЗМОЖЕН из процессора                                      │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ ИСТОЧНИК 2: Ретроэкспорт (массовый + при коррекции вида)                     │
│                                                                             │
│  VideoSpecies.frames (bbox) → extract_detection_frame_cropped(video, bbox)   │
│                                                                             │
│  require_bbox=True → при отсутствии bbox НЕ сохраняем (return False)        │
│  НО: extract_detection_frame_cropped при ОШИБКЕ возвращает full frame!       │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 Корневая причина: `extract_detection_frame_cropped`

**Файл:** `app/web/services/detection_crop_service.py`

```python
def extract_detection_frame_cropped(video_path, offset_sec, bbox_norm):
    jpeg_bytes = extract_detection_frame(video_path, offset_sec)
    if not jpeg_bytes or not bbox_norm or len(bbox_norm) != 4:
        return jpeg_bytes   # ← full frame при отсутствии bbox
    try:
        # ... crop logic ...
        if x2 <= x1 or y2 <= y1:
            return jpeg_bytes   # ← full frame при невалидном bbox
        # ...
    except Exception as e:
        logger.warning("Crop failed, using full frame: %s", e)
        return jpeg_bytes   # ← full frame при любой ошибке!
```

**Проблема:** При любой ошибке (невалидный bbox, cv2 fail, exception) функция возвращает **полный кадр**, а вызывающий код **сохраняет его в датасет**.

**Вызов:** `extract_and_save_crop_for_detection` вызывает эту функцию и при успехе пишет результат в файл. Если результат — full frame, он всё равно сохраняется.

### 2.3 Исторический фактор

В `DATASET_COLLECTION_BRAINSTORM.md` указано:
> «Старые фото не кропнуты — ретроэкспорт без bbox давал полный кадр → **исправлено**: пропуск при отсутствии bbox»

Исправление добавило `require_bbox=True` — при **отсутствии** bbox мы не вызываем extract. Но при **наличии** bbox с ошибкой кропа — fallback на full frame остался. Плюс старые записи до исправления.

### 2.4 Сводка причин full-frame в датасете

| # | Причина | Когда | Статус |
|---|---------|-------|--------|
| 1 | Ретроэкспорт до require_bbox | Старый код сохранял full frame при отсутствии bbox | Исправлено, но старые файлы остались |
| 2 | Fallback в extract_detection_frame_cropped | bbox невалидный (x2≤x1), cv2 fail, exception | **Баг: до сих пор сохраняет full frame** |
| 3 | Процессор | best_frame всегда crop | Исключено |

## 3. Вопросы пользователя и ответы

### 3.1 «Надо чистить датасет?»

**Да.** Существующие full-frame файлы нужно выявить и удалить (или переэкспортировать).

**Как выявить full-frame:**
- Эвристика: соотношение сторон и размер. Кроп птицы обычно не 16:9 и не 1920×1080.
- Порог: если ширина × высота > N пикселей (например, 800×600) — подозрение на full-frame.
- Точнее: сравнить с разрешением исходного видео (если известно).

**Рекомендация:** Скрипт/кнопка «Найти подозрительные full-frame» → предпросмотр → удалить или заменить ретроэкспортом.

### 3.2 «Нужна кнопка или при реэкспорте он должен чиститься?»

**Оба варианта полезны, но с разной семантикой:**

| Опция | Описание | Когда использовать |
|-------|----------|---------------------|
| **Кнопка «Очистить датасет»** | Удалить файлы, не соответствующие БД (осиротевшие, full-frame по эвристике) | Ручная зачистка, разовая миграция |
| **Ретроэкспорт «пересобрать за период»** | Удалить crops за период и заново извлечь только кропы из видео | Гарантированно только кропы за выбранный период |

**Рекомендация:**
1. **Ретроэкспорт** — добавить режим «Пересобрать»: для выбранного периода удалить существующие файлы датасета и заново извлечь только кропы (с require_bbox, без fallback на full frame).
2. **Отдельная кнопка «Очистить датасет»** — для удаления: (a) осиротевших файлов, (b) подозрительных full-frame по эвристике.

### 3.3 «При экспорте поступает новый сформированный датасет за период?»

**Текущее поведение:**
- **Экспорт ZIP** — читает `data/dataset/train/` и `val/`, фильтрует по периоду (video_id) и only_manually_corrected. **Не пересобирает** — просто упаковывает то, что уже лежит на диске.
- **Ретроэкспорт** — **дополняет** датасет: извлекает кадры из видео и добавляет в train/. Не удаляет старые файлы. Пропускает, если файл уже есть.

**Итого:** Экспорт не формирует «новый» датасет — он упаковывает существующий с фильтрами. Ретроэкспорт дополняет, не заменяет.

**Желаемое поведение (для «чистого» датасета за период):**
- Режим «Пересобрать датасет за период»:
  1. Удалить из train/ все файлы, относящиеся к видео за период (по video_id в имени).
  2. Заново извлечь кропы только из VideoSpecies за период (с валидным bbox).
  3. Результат — датасет за период содержит только кропы.

## 4. Предлагаемые изменения (приоритет)

### P0 — Исправить баг fallback на full frame

**Файл:** `app/web/services/detection_crop_service.py`

**Изменение:** При `require_crop=True` (новый параметр или контекст) — никогда не возвращать full frame. При ошибке кропа возвращать `None`.

**Вариант:** Добавить параметр `allow_fallback_full_frame: bool = False`. При вызове из dataset-экспорта передавать `False`. При вызове для iNaturalist/превью — можно оставить fallback.

Или проще: в `extract_detection_frame_cropped` при любой ошибке возвращать `None` вместо `jpeg_bytes`. Вызывающий код (dataset) уже проверяет `if not jpeg_bytes: return False`. Тогда full frame никогда не попадёт в датасет.

### P1 — Режим «Пересобрать» в ретроэкспорте

**API:** `POST /api/ui/dataset/retro-export` с параметром `rebuild: true`.

**Логика:**
1. По периоду (start_date, end_date) получить video_ids.
2. Удалить из `train/<Species>/` все файлы с именами `{video_id}_*.jpg` для этих video_ids.
3. Выполнить ретроэкспорт как сейчас (только кропы, require_bbox).

**Результат:** Датасет за период содержит только свежеизвлечённые кропы.

### P2 — Кнопка «Очистить датасет»

**Действия:**
1. **Осиротевшие файлы:** удалить файлы, для которых нет VideoSpecies с (video_id, track_id) и тем же видом. *Риск:* processor-файлы с index не имеют vs.id — маппинг приблизительный.
2. **Подозрительные full-frame:** по эвристике (размер, соотношение сторон) пометить/удалить. Опционально — предпросмотр перед удалением.

**Рекомендация:** Начать с простого — удаление по эвристике размера (например, > 1 Мпкс и aspect ratio близок к 16:9). С предупреждением и подтверждением.

### P3 — Валидация при экспорте

При сборке ZIP — проверять каждый файл: если подозрение на full-frame (эвристика), исключать из архива и логировать. Опционально — отчёт «исключено N подозрительных full-frame».

## 5. Семантика операций (сводная таблица)

| Операция | Что делает | Результат |
|----------|------------|-----------|
| **Ретроэкспорт (дополнение)** | Извлечь кропы из видео за период, добавить в train/ | Датасет дополнен, старые файлы не трогаются |
| **Ретроэкспорт (пересборка)** | Удалить crops за период, заново извлечь только кропы | Датасет за период = только кропы |
| **Очистить датасет** | Удалить осиротевшие + подозрительные full-frame | Меньше мусора |
| **Экспорт ZIP** | Упаковать train/val с фильтрами (период, manually_corrected) | Архив для Colab/обучения |

## 7. Риски и митигации

| Риск | Митигация |
|------|-----------|
| Ложное срабатывание эвристики full-frame | Консервативные пороги; предпросмотр перед удалением |
| Потеря данных при «Пересобрать» | Явное подтверждение: «Будут удалены все crops за период и извлечены заново» |
| Processor-файлы (video_id_track_id_index) — маппинг на VideoSpecies неточный | Очистка «осиротевших» — только для файлов с однозначным маппингом; processor-файлы не трогать или по video_id |
