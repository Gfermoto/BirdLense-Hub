# Пропущенные события: диагностика

Когда BirdLense и Frigate-Notify оба пропускают событие — причина обычно **до** нотификаторов: Frigate не зафиксировал детекцию или MQTT не доставил событие.

## Цепочка событий

```
Камера (RTSP) → go2rtc → Frigate (detect) → MQTT → BirdLense / Frigate-Notify
```

Если событие не пришло — проверять по цепочке снизу вверх.

---

## 1. Ошибки из ваших логов (18.03.2026)

### BirdBox (06:51:40)

| Ошибка | Причина |
|--------|---------|
| `non monotonically increasing dts` (audio) | Проблемы с аудиопотоком камеры — некорректные timestamps |
| `Connection timed out` | Камера/сеть перестала отвечать |
| `404 Not Found` на `rtsp://192.168.1.11:8554/BirdBox` | go2rtc не отдаёт поток (источник упал) |
| `Invalid data found when processing input` | Повреждённые данные при переподключении |
| `No route to host` (Forest, Termal_forest) | Сеть до 192.168.1.101 недоступна |

### Итог

В момент сбоя Frigate **не получал стабильный поток** с BirdBox. Без потока нет детекций → нет MQTT-событий → BirdLense и Frigate-Notify не получают ничего.

---

## 2. Что проверить

### Сеть и камеры

- **Ping** до камер (192.168.1.129, 192.168.1.101) — стабильность
- **Wi‑Fi** — если камеры по Wi‑Fi, возможны обрывы
- **Перегрузка** — много камер на одном свитче/маршрутизаторе

### go2rtc

- Логи go2rtc: `i/o timeout` к 192.168.1.50 — камера или сеть до неё
- После падения камеры go2rtc возвращает 404, пока источник не восстановится

### Frigate

- `ffmpeg process crashed` — Frigate перезапускает ffmpeg, но при 404 от go2rtc запись не идёт
- В этот период детекции не работают

### MQTT

- Брокер доступен? `mosquitto_sub -t 'frigate/#' -v`
- События приходят? При детекции должны быть сообщения в `frigate/events` и т.п.

---

## 3. Рекомендации

### Камера BirdBox (192.168.1.129)

1. **Аудио** — DTS-ошибки часто от нестабильного аудиопотока. Варианты:
   - Обновить прошивку камеры
   - Проверить настройки аудио (sample rate, codec)
   - BirdLense записывает видео с аудио, если оно есть в потоке — отключать не рекомендуется

2. **Сеть** — перевести на провод, если возможно

3. **Таймауты** — в конфиге Frigate для BirdBox можно увеличить `ffmpeg` timeout (если версия поддерживает)

### go2rtc

- Убедиться, что go2rtc и камеры в одной стабильной сети
- Проверить, что камера не «засыпает» и не обрывает RTSP при простое

### Резервный триггер

Если Frigate часто падает из‑за камеры — в BirdLense можно включить **OpenCV** или **ESPHome** как запасной триггер записи (см. Настройки → Детекция движения).

---

## 4. Быстрая проверка

```bash
# MQTT — видно ли события Frigate?
mosquitto_sub -h localhost -t 'frigate/#' -v

# go2rtc — есть ли поток BirdBox?
curl -s http://192.168.1.11:1984/api/streams | jq .
```

Если MQTT пустой при явной детекции в Frigate UI — проблема в MQTT. Если Frigate не показывает событие — проблема в камере/go2rtc/Frigate.
