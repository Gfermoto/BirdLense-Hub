# Консилиум: мозговой штурм и ресерч

Дополнения, идеи и улучшения к плану модернизации BirdLense.

---

## 1. Видео и запись

### 1.1 Ring buffer (предзапись)

**Проблема:** При триггере MQTT/Frigate момент «прилёта птицы» уже прошёл — запись начинается с опозданием.

**Идея:** Кольцевой буфер в памяти (5–15 сек) — непрерывно пишем кадры, при триггере сохраняем «до + после». Как в CCTV/Frigate.

**Реализация:** Отдельный поток пишет в `deque` или FFmpeg segment muxer. При триггере — склейка сегментов.

**Ссылки:** [mp4ring](https://github.com/dreddsa5dies/mp4ring), [seccam](https://github.com/Battleroid/seccam)

---

### 1.2 Несколько камер / потоков

**Идея:** Поддержка нескольких потоков Go2RTC (кормушка + обзор, несколько кормушек).

**Конфиг:** `video.streams: [{name: "feeder", url: "..."}, {name: "overview", url: "..."}]`

**Сложность:** Маппинг камеры Frigate → поток BirdLense, выбор потока для записи.

---

### 1.3 Аудио в потоке

**Вопрос:** Есть ли аудио в RTSP/HLS от камеры?

**Если да:** FFmpeg при записи сохраняет аудио → спектрограммы без отдельного микрофона.

**Если нет:** BirdNET по MQTT — единственный аудио-источник; спектрограммы опционально (из другого устройства?).

## 2. Синхронизация и дедупликация

### 2.1 Временное окно для слияния

**Проблема:** YOLO, Frigate и BirdNET дают события в разное время. Один визит — три источника с разными timestamp.

**Идея:** Окно слияния (например, ±5 сек). Детекции в окне считаются одним событием. Правило: YOLO primary, Frigate/BirdNET повышают confidence или добавляют вид, если YOLO не определил.

**Реализация:** При сохранении видео — поиск MQTT-событий в `[start_time - 5s, end_time + 5s]`, слияние по виду и времени.

---

### 2.2 Дедупликация по виду

**Проблема:** Одна и та же птица — несколько детекций за короткий период (YOLO по кадрам, Frigate update, BirdNET повтор).

**Идея:** Окно дедупликации (30–60 сек) для одного вида. Если «House Sparrow» уже зафиксирован в этом окне — не создавать новый визит, обновить существующий (end_time, confidence).

---

### 2.3 Нормализация названий видов

**Проблема:** Frigate (INat), BirdNET, YOLO (NABirds) — разные таксономии. «House Sparrow» vs «house_sparrow» vs «Passer domesticus».

**Идея:** Словарь маппинга в конфиге или использование [IOC World Bird List](https://worldbirdnames.org/) / eBird Taxonomy как эталона.

**Реализация:** `species_normalizer.py` — приведение к единому формату (common name, scientific optional). Конфиг: `species_mapping: { "house_sparrow": "House Sparrow" }`.

## 3. Погода и контекст

### 3.1 Погода — HA вместо OpenWeather

**Текущее:** OpenWeather API, свой ключ.

**Идея:** Интеграция с HA — `weather.home` или `sensor.outside_temperature`. Меньше внешних зависимостей, данные уже есть в HA.

**Конфиг:** `weather.source: openweather | homeassistant`, `weather.ha_entity_id: "weather.home"`.

---

### 3.2 Геолокация

**Текущее:** lat/lon в конфиге для BirdNET regional species.

**Идея:** При MQTT-only BirdNET даёт свои координаты. Но для YOLO regional species list и для погоды — координаты нужны. Оставить в конфиге, опционально синхронизировать с HA `zone.home`.

## 5. Home Assistant и экосистема

### 5.1 HA Add-on / Integration

**Идея:** Официальный или community add-on для HA — установка в один клик, автоконфиг MQTT, discovery.

**Сложность:** Средняя. Требует отдельный репозиторий add-on.

---

### 5.2 Автоматизации по видам

**Идея:** BirdLense публикует `birdlense/detections` с полем `species`. В HA — automation: «Если species == "Northern Cardinal" → включить корм на 30 сек».

**Реализация:** MQTT publish при каждой значимой детекции. Формат: `{"species": "Northern Cardinal", "confidence": 0.92, "source": "yolo", "timestamp": "..."}`.

---

### 5.3 Дашборд HA

**Идея:** Lovelace-карточки: последние визиты, топ видов, кнопка «Подать корм». Данные через REST API BirdLense или MQTT sensors.

## 6. Хранение и экспорт

### 6.1 Политика хранения

**Вопрос:** Сколько хранить видео? Месяц? Год? Только метаданные?

**Идея:** Конфиг `retention.days` или `retention.max_gb`. Cron/фоновый процесс удаляет старые записи. Опционально — архив на NAS (rsync, rclone).

---

### 6.2 Экспорт в citizen science

**Идея:** Экспорт наблюдений в iNaturalist или eBird (если поддерживают API).

**Ссылки:** [iNaturalist API](https://www.inaturalist.org/pages/api+recommended+practices), eBird Data Download.

**Сложность:** Высокая. Требует аккаунты, маппинг таксономии, ручная верификация.

---

### 6.3 Бэкап SQLite

**Идея:** Периодический dump БД (sqlite3 .backup) на NAS или в HA-accessible папку. Восстановление при сбое.

---

## 7. LLM-верификация

### 7.1 Сохранить ли?

**Текущее:** Gemini проверяет низкоконфайденсные детекции.

**С MQTT-подтверждениями:** Frigate + BirdNET уже дают второе мнение. LLM — опционально для спорных случаев.

**Рекомендация:** Оставить как опцию. При `ai.gemini_api_key` — верификация. При совпадении YOLO + BirdNET — можно пропускать LLM.

---

### 7.2 Альтернативы Gemini

**Идея:** Поддержка локальных LLM (Ollama, LM Studio) через OpenAI-совместимый API. Без облака.

---

## 8. Производительность и надёжность

### 8.1 Переподключение к потоку

**Проблема:** RTSP/HLS обрывается (сеть, перезагрузка Go2RTC).

**Идея:** Автореконнект с экспоненциальным backoff. Логирование обрывов. Health check — если нет кадров N секунд, переподключиться.

---

### 8.2 MQTT reconnect

**Идея:** paho-mqtt / aiomqtt с `clean_session=False`, `last_will`. При падении — HA видит offline.

---

### 8.3 Graceful degradation

**Сценарии:**
- Go2RTC недоступен → только MQTT-события, без записи видео
- MQTT недоступен → только OpenCV + YOLO
- YOLO не загружается → только MQTT-детекции

**Идея:** Режимы fallback, не падать полностью. UI показывает статус компонентов (video: ok, mqtt: ok, yolo: ok).

---

## 9. Безопасность

### 9.1 Секреты

**Рекомендация:** Все секреты (API keys, MQTT password, HA token) — через env, не в конфиге. `.env.example` без реальных значений.

**Идея:** BirdLense в отдельной Docker network, доступ только к нужным сервисам (Go2RTC, MQTT, HA). Не открывать наружу без необходимости.

3. **Мобильная версия** — текущий UI уже responsive?
