# Re-ID — дорожная карта (#374)

[English](./REID_ROADMAP.md)

**Статус:** исследование / дизайн, в продукт по умолчанию не везено.

## Цели

- Один и тот же индивид на разных визитах: **metric learning** или **эмбеддинг** поверх кропов детектора; сглаживание во времени с ID из ByteTrack.

## Backbone — DINO / DINOv2 (запланированный кандидат)

**Роль:** замороженный или слегка дообученный **ViT** на кропах детектора даёт вектор фиксированной размерности для косинусной близости / metric learning — учёт в [#374](https://github.com/Gfermoto/BirdLense-Hub/issues/374).

**Что это вам даёт**

- **Тонкие визуальные признаки** при умеренной разметке «тот же веснушчатый дятел, что вчера»: у предобучения в духе DINO хороший перенос, когда подписанных индивидуумов мало, в отличие от чистой классификации по виду.
- **Кластеризация по внешности**, а не только по таксону — ближе к **индивидуальному** Re-ID (кормушка, разные дни), чем к EU/US классификатору видов.
- Привычный стек (**PyTorch**, timm / torch.hub) для прототипов; путь в прод (задержка, при необходимости ONNX) — отдельная валидация на вашем железе.

**Чем не заменяет**

- **Бинарный детектор** и **классификатор видов** остаются основной веткой продукта, пока вы явно не меняете ТЗ. Re-ID — **надстройка**: дополнительное вычисление на кроп или на визит.

**Компромиссы**

- **Задержка и VRAM** относительно «только классификатор»; цена растёт с разрешением кропа и размерностью эмбеддинга.
- Сильные эмбеддинги всё равно требуют **политики** (пороги, старение галереи, «новый индивид») — см. приёмка в англ. версии roadmap.

## Классификация видов — тот же backbone (опционально)

DINO/DINOv2 нужен **не только** для Re-ID особи. Тот же backbone может улучшить **виды** и разметку:

- **Дообучение**: голова классификации на кропах детектора — перенос с SSL часто выгоднее на малом датасете, чем учить маленькую сеть «с нуля».
- **Разметка и active learning**: поиск похожих кропов, пары для разметки, приоритет батчей ([#369](https://github.com/Gfermoto/BirdLense-Hub/issues/369)); пересекается с дорожкой классификатора ([#370](https://github.com/Gfermoto/BirdLense-Hub/issues/370)).

**Один экземпляр на сервере (цель по дизайну):** один проход ViT на кроп может одновременно кормить **голову видов** и **эмбеддинг для Re-ID**, если это собрать в одном графе — обычно **одна** загрузка backbone в память вместо двух несвязанных моделей. Платите **одним forward + тонкими головами**, когда включены оба пути; флагами можно отключить Re-ID или считать эмбеддинги офлайн/пакетами, чтобы не перегружать хаб.

Прототип [#383](https://github.com/Gfermoto/BirdLense-Hub/issues/383) начинает с галереи Re-ID; эксперименты по видам остаются здесь до переноса в [TRAINING.ru.md](./TRAINING.ru.md) и процессор.

### Офлайн-скрипт в репозитории

- **`scripts/reid/embed_dinov2_crop.py`** — загрузка DINOv2 через `torch.hub`, L2-нормированный эмбеддинг на файл; вывод JSON Lines. См. **`scripts/reid/README.md`**. Нужны PyTorch + torchvision + Pillow в среде обучения/экспериментов (не обязательный dependency Docker-процессора).
- **`scripts/reid/embed_cosine_report.py`** — статистика pairwise cosine, опционально **top-K соседей**, файл пар `--pairs` для контроля «та же особь» vs случайные пары (отчёт Markdown). Нужен только **numpy**.
