# Instructions for coding agents (Cursor, etc.)

## Доводить работу до конца

Агент **сам** завершает цикл, без напоминаний, если задача это предполагает:

1. **Код** — правки согласованы с существующим стилем; по возможности прогнать релевантные тесты / линтер локально (`app/.venv`, `make test-web` в CI уже дублирует часть).
2. **Документация и журнал** — при заметных изменениях для пользователей/операторов: обновить нужные `docs/*`, при необходимости [CHANGELOG.md](CHANGELOG.md).
3. **Git** — не оставлять осмысленных незакоммиченных хвостов; коммиты с понятными сообщениями; **push** в соответствующую ветку (`dev`), если пользователь не просил только локальный черновик.
4. **GitHub** — если накопились коммиты на `dev`, которые должны быть на проде: открыть **PR `dev` → `main`**, дождаться **зелёного CI**, **смержить**; при необходимости подтянуть `dev` к `main`.  
   **Отчётность:** любая сданная работа — **Issue** (завести, если не было), комментарий (итог + PR), **закрыть**; на доске **BirdLense Hub — Roadmap** → **Done** (`scripts/github-project-mark-done.sh` при PAT `project`). Не плодить отдельные доки — вести **ROADMAP**, **Issues** и доску. См. [docs/ROADMAP.ru.md](docs/ROADMAP.ru.md) / [EN](docs/ROADMAP.md) и [CONTRIBUTING.ru.md](CONTRIBUTING.ru.md) § *Issues и доска*.
5. **Деплой хаба** — после изменений кода приложения, которые должны быть на сервере: из корня репозитория **`make deploy`** (см. [.cursor/rules/deploy.mdc](.cursor/rules/deploy.mdc) — сервер, исключения rsync, данные).
6. **Проверка** — после деплоя убедиться, что health / логи в порядке; после правок CI — дождаться успешного прогона, если запускали workflow.

Исключения: пользователь явно просит «только черновик», «не пушить», «без деплоя» — тогда урезать цикл.
